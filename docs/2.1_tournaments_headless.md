# Tournaments Headless

Fetch pool tournaments, render your own tournament UI, and join headlessly. For the shared mechanics every call here relies on — the invisible iframe, lifecycle gating, timeouts, and the full error table — see [Headless on Web](2.0_headless.md).

Five functions make up the surface:

| Function | Auth | Purpose |
| --- | --- | --- |
| `api.tournaments()` | **None** (pre-auth allowed) | List recommended pool tournaments |
| `api.tournament(matchupId)` | Logged-in user | One tournament's full detail |
| `api.tournamentLeaderboard(matchupId, pagination?)` | Logged-in user | One leaderboard page |
| `api.joinTournament(tournamentId)` | Logged-in user | Join; resolves with the joined `matchupId` |
| `api.autoJoinTournaments()` | Logged-in user | Enroll in every eligible free tournament; resolves with `matchupIds` |

## Wire shapes are raw

Tournament payloads mirror the raw types returned by the Lucra app **verbatim** — snake_case where the schema is snake_case (`starts_at`, `buy_in_amount`, `pool_tournament_details`), camelCase only where the schema itself is (`matchupId`, `canJoinTournament`). No mapping layer exists on either side; reshape into your own view models in your app.

## Listing tournaments

`api.tournaments()` resolves with the list of recommended pool tournaments. **This is the one headless call allowed before auth**: it awaits iframe initialization internally (no `await client.ready` needed) and works for logged-out users, so you can render a tournament list before the user logs in.

```typescript
const { tournaments } = await client.api.tournaments();
```

Each `LucraTournament` list item:

| Field | Type | Notes |
| --- | --- | --- |
| `matchupId` | `string` | Pass to `tournament()`, `tournamentLeaderboard()`, `joinTournament()` |
| `canJoinTournament` | `boolean \| null` | Whether the current session may join |
| `matchup.starts_at` / `matchup.expires_at` | `string \| null` | ISO timestamps |
| `matchup.pool_tournament_details` | object \| null | `title`, `buy_in_amount`, `icon_url`, `game_id`, `type` |
| `matchup.pool_payout_reward_structures` | array | `{ place, value, type }` per payout place |
| `matchup.pool_tournament_leaderboard_aggregate` | object | `aggregate.count` — current participant count |

## Tournament detail

`api.tournament(matchupId)` resolves with a single tournament's full detail. Requires a logged-in user — call after `client.ready`.

```typescript
await client.ready;
const { tournament } = await client.api.tournament(matchupId);
```

`tournament` is a `LucraTournamentDetail | null`. The shape is large (it powers Lucra's own detail screen); the fields most integrations need:

| Field | Type | Notes |
| --- | --- | --- |
| `title`, `description`, `image_url` | strings | Display |
| `buy_in_amount`, `free_buy_in` | `number \| null`, `boolean` | Cost to enter |
| `status`, `is_completed`, `is_expired`, `is_not_started` | mixed | Lifecycle |
| `starts_at`, `expires_at`, `timer` | mixed | Scheduling; `timer` is `{ caption, state }` |
| `payout_structure` | object \| null | `title`, `description`, `rewards[]` with per-place labels |
| `leaderboard` | object \| null | Same shape as the leaderboard call below |
| `user_leaderboard_row` | object \| null | The current user's own row |
| `total_participants`, `max_participants` | `number \| null` | Capacity |
| `attempt_data` | object \| null | Replayability: `attempts_remaining`, `can_join_tournament`, `is_replayable`, `scores[]` |
| `how_to_play` | array \| null | `{ step, text }` instructions |
| `terms`, `notices` | arrays | Confirmation terms and warnings to surface before joining |

The full type is `LucraTournamentDetail` in the SDK's exported types.

## Leaderboard pages

`api.tournamentLeaderboard(matchupId, pagination?)` resolves with one leaderboard page. Requires a logged-in user.

```typescript
const { ui_tournament_details } = await client.api.tournamentLeaderboard(matchupId, {
  limit: 20,
  offset: 0,
});
const leaderboard = ui_tournament_details?.leaderboard;
```

`leaderboard` carries:

| Field | Type | Notes |
| --- | --- | --- |
| `rows` | `LucraLeaderboardRow[]` | `{ name, payout, points, rank, userId }` |
| `columns` | `LucraLeaderboardColumn[]` | `{ label, name }` — render headers from these |
| `pagination` | `{ limit, offset, total_count }` | Drive paging from `total_count` |

Pages are independent — merge rows client-side as you fetch:

```typescript
async function allRows(matchupId: string, pageSize = 20) {
  const rows: LucraLeaderboardRow[] = [];
  let offset = 0, total = Infinity;
  while (offset < total) {
    const { ui_tournament_details } = await client.api.tournamentLeaderboard(matchupId, {
      limit: pageSize,
      offset,
    });
    const lb = ui_tournament_details?.leaderboard;
    if (!lb) break;
    rows.push(...lb.rows);
    total = lb.pagination.total_count;
    offset += pageSize;
  }
  return rows;
}
```

Remember requests are single-flight per function: fetch pages sequentially, not in parallel — a second in-flight `tournamentLeaderboard` call cancels the first.

## Joining a tournament

`api.joinTournament(tournamentId)` requests joining the tournament and resolves with the joined `matchupId`. Requires a logged-in user. This is the call that exercises the full **call → typed error → present a remediation flow → retry** loop, because joining is where verification, funds, and location are enforced.

```typescript
import { LucraApiError, LucraApiErrorCode } from 'lucra-web-sdk';

async function join(tournamentId: string) {
  try {
    const { matchupId } = await client.api.joinTournament(tournamentId);
    return matchupId;
  } catch (e) {
    if (!(e instanceof LucraApiError)) throw e; // "Timeout" / cancellation strings
    switch (e.code) {
      case LucraApiErrorCode.unverified: {
        const dialog = client.dialog().kyc();
        client.on('kycComplete', function onDone() {
          client.off('kycComplete', onDone);
          dialog.close();
          join(tournamentId); // retry
        });
        break;
      }
      case LucraApiErrorCode.demographicInformationMissing: {
        const dialog = client.dialog().demographic();
        client.on('demographicComplete', function onDone() {
          client.off('demographicComplete', onDone);
          dialog.close();
          join(tournamentId); // retry
        });
        break;
      }
      case LucraApiErrorCode.insufficientFunds: {
        // Deposit runs in a real popup window, not the iframe (Apple Pay).
        const popup = client.popup().deposit();
        popup.onClose((result) => {
          if (result?.toastType === 'success') join(tournamentId); // retry
        });
        break;
      }
      case LucraApiErrorCode.locationNeeded: {
        const dialog = client.dialog().locationGrant();
        client.on('locationGranted', function onDone() {
          client.off('locationGranted', onDone);
          dialog.close();
          join(tournamentId); // retry
        });
        break;
      }
      case LucraApiErrorCode.locationError:
        // Location check failed. e.message says whether Lucra rejected the region
        // (do not retry) or the browser's geolocation failed (retry once the user
        // allows location). Show your own "location unavailable" state.
        break;
      case LucraApiErrorCode.apiError:
        // Catch-all; e.message carries the detail. Safe to retry.
        break;
    }
  }
}
```

Notes on the loop:

- Remove each completion listener with `off()` once it fires (as above) so a repeated failure doesn't stack duplicate retries.
- Every code's meaning, remediation, and retry-appropriateness is tabulated in [Headless on Web → Errors](2.0_headless.md#errors).
- A successful join also fires the `tournamentJoined` event (`{ matchupId }`) — the same signal emitted when a user joins through Lucra's own UI, so one listener covers both paths. See [Lucra Event Listener](1.6_lucra_event_listener.md).

## Auto-joining free tournaments

By default Lucra enrolls an authenticated user in every eligible free tournament automatically, once per sign-in — that is the `autoJoin: true` constructor default (see [autoJoin](1.2_initialize_client.md#autojoin)). Initialize with `autoJoin: false` to take over the timing, then call `api.autoJoinTournaments()` at the moment you choose. Requires a logged-in user.

```typescript
await client.ready;
const { matchupIds } = await client.api.autoJoinTournaments();
```

- Resolves with the matchup ids the user was enrolled in on this call. An **empty array is a normal result** — the user was already in everything they were eligible for.
- The `autoJoinedTournaments` event (`{ matchupIds: string[] }`) fires for both this manual call and the automatic sign-in trigger, so one listener covers both paths. See [Lucra Event Listener](1.6_lucra_event_listener.md#available-events).
- Enrollment completes asynchronously on Lucra's side: a `tournament()` or `tournamentLeaderboard()` read issued immediately after may not list the user as a participant yet.
- A skipped or failed enrollment rejects with a typed `LucraApiError` — `LOCATION_NEEDED`, `DEMOGRAPHIC_INFORMATION_MISSING`, `LOCATION_ERROR`, or `API_ERROR` — and no event fires. Remediate per the [error table](2.0_headless.md#errors); `UNVERIFIED` and `INSUFFICIENT_FUNDS` do not apply because the tournaments are free.
- An `API_ERROR` whose `message` begins `Auto-join skipped:` names a precondition, not a transient failure: the feature is not enabled for the tenant, the account is restricted, or the user profile was unavailable. Retrying does not change it.

## Handing off to Lucra's tournament UI

To show Lucra's own tournament detail screen instead of (or after) rendering your own, navigate the iframe: `client.redirect().tournamentDetails(matchupId)`, or present it as an overlay with `client.dialog().tournamentDetails(matchupId)`. See [Lucra Flows](1.3_lucraflows.md).
