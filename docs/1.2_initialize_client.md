# Initializing the LucraClient

Import from `lucra-web-sdk`. The client enforces a singleton - only one instance can exist at a time.

**Initialize once at app startup:**

```typescript
import { LucraClient } from 'lucra-web-sdk';

LucraClient.initialize({
  apiKey: "<your Lucra api key>",
  tenantId: "<your Lucra tenant id>",
  env: "sandbox",
});
```

**Retrieve the instance anywhere:**

```typescript
import { LucraClient } from 'lucra-web-sdk';

const client = LucraClient.getInstance();
```

Calling `initialize` a second time throws. Calling `getInstance` before `initialize` throws.

## Mount the iframe at startup (recommended)

Right after `initialize`, mount the Lucra iframe once, hidden, into a host element that stays in the DOM for the life of your app:

```typescript
import { LucraClient } from 'lucra-web-sdk';

LucraClient.initialize({
  apiKey: "<your Lucra api key>",
  tenantId: "<your Lucra tenant id>",
  env: "sandbox",
});

// Any element that is never removed, e.g. one created once at startup.
const host = document.createElement("div");
document.body.appendChild(host);

LucraClient.getInstance().open(host, undefined, { hidden: true }).home();
```

The embedded Lucra app only starts listening for SDK messages once it has booted (auth, tenant config, SDK init), and it drops anything sent earlier. Mounting at startup starts that boot immediately, so `initialized` and `ready` resolve sooner and the window in which messages can be dropped is as short as possible. Calls that need the iframe also stop throwing [`LucraClientNotOpen`](2.0_headless.md#lucraclientnotopen), `api.tournaments()` can serve pre-auth lists, and you avoid the reload caused by mounting late per screen or by re-parenting with the deprecated `moveTo()`.

`{ hidden: true }` hides only the iframe (`display: none`); your app lays out the host element as usual. Register `.on()` listeners before or right after the mount. Then:

- Present Lucra as a fullscreen overlay with [`dialog()`](1.3_lucraflows.md#dialogs) (no reload), or inline with `show()` / `hide()`. If your app hides the host element itself, `show()` alone will not reveal it, but `dialog()` will, because it restyles the host.
- Read data for your own UI with the headless [`api.*`](2.0_headless.md) calls.
- For deposits, present `wallet()` or `profile()` (for example `dialog().wallet()`): from there the Lucra app opens Add Funds in a popup on its own.
- Navigate with `redirect()` or `dialog()`. Do not call `open()` again to move the iframe: once it exists, `open(element)` ignores `element` and navigates in place (`open(host).login()` instead reloads it to reach the login screen).

## Constructor properties

| Property | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `apiKey` | `string` | Yes | — | Your Lucra API key |
| `tenantId` | `string` | Yes | — | Your Lucra tenant id |
| `env` | `LucraEnvironment` | Yes | — | Which Lucra environment to connect to |
| `locationId` | `string` | No | `""` | Identifies the physical location the session belongs to |
| `autoJoin` | `boolean` | No | `true` | Whether Lucra enrolls the user in eligible free tournaments automatically |

### autoJoin

By default Lucra enrolls an authenticated user in every eligible free tournament they are not already in, once per sign-in, and reports the result through the [`autoJoinedTournaments`](1.6_lucra_event_listener.md#available-events) event. Nothing is required of the embedding app.

Pass `autoJoin: false` to turn the automatic enrollment off:

```typescript
LucraClient.initialize({
  apiKey: "<your Lucra api key>",
  tenantId: "<your Lucra tenant id>",
  env: "sandbox",
  autoJoin: false,
});
```

With `autoJoin: false`, Lucra never enrolls the user on its own and it becomes your app's decision when to do so. Trigger it with [`api.autoJoinTournaments()`](1.6_lucra_event_listener.md#async-api), which enrolls the user at that moment and reports through the same `autoJoinedTournaments` event.

Enrollment is subject to Lucra's own conditions either way: the user must be signed in, have complete profile information, be in good standing, have granted the browser location access, and belong to a tenant with the feature enabled. When a condition is not met the call is skipped silently and no event fires.

**Cleanup (e.g. on logout):**

```typescript
LucraClient.destroy();
```

After `destroy`, `initialize` can be called again.

**React example:**

```typescript
// app entry point (e.g. main.tsx)
import { LucraClient } from 'lucra-web-sdk';

const client = LucraClient.initialize({
  apiKey: "<your Lucra api key>",
  tenantId: "<your Lucra tenant id>",
  env: "production",
});

// Mount once, hidden, right away (see "Mount the iframe at startup").
const host = document.getElementById("lucra-host")!;
client.open(host, undefined, { hidden: true }).home();
```

```typescript
// any component
import { LucraClient } from 'lucra-web-sdk';

function MyComponent() {
  const client = LucraClient.getInstance();
  // ...
}
```

## Awaiting Initialization

The client exposes `ready` (a Promise), `isInitialized` (a boolean), and `user` (the current Lucra user, or `null`) so consumers can know when the iframe has finished initializing.

`ready` resolves once the iframe has initialized and the user is logged in. It rejects if initialization fails, or with `LucraUserNotLoggedIn` when the user is not logged in, so a single `await` covers both checks. `ready` does not settle until the iframe is mounted, so [mount it at startup](#mount-the-iframe-at-startup-recommended).

```typescript
import { LucraClient, LucraUserNotLoggedIn } from 'lucra-web-sdk';

// `host` was mounted at startup (see "Mount the iframe at startup").
const client = LucraClient.getInstance();

try {
  await client.ready;
  const user = client.user;
} catch (err) {
  if (err instanceof LucraUserNotLoggedIn) {
    client.open(host).login();
  }
}
```

You can also subscribe to the `initialized` event for the initialization signal.
