# React (preview)

> **This is a preview.** It is built on the [headless client](3.0_headless_client.md), which is a preview too. Its API can still change while it is a preview. Tell your Lucra contact what works and what does not.

`lucra-web-sdk/react` connects the headless client to React: a provider, and hooks for the state that changes on its own.

## Setup

- Needs React 18 or later. `react` is an optional peer dependency: `lucra-web-sdk` and `lucra-web-sdk/headless` do not need it.
- Create the client once, at module scope, with `createLucraClient`, as in [Setup](3.0_headless_client.md#setup). Never during render or in an effect.
- Wrap the app in `<LucraProvider client={lucra}>`.
- The provider never creates or destroys the client. Route loaders and other code outside React keep using the same `lucra`.
- A bundler that does not read the `exports` field (webpack 4, for example) cannot find `lucra-web-sdk/react`. Point an alias at `lucra-web-sdk/dist/react/index.js`.

```tsx
import { createLucraClient } from "lucra-web-sdk/headless";
import { LucraProvider } from "lucra-web-sdk/react";
import type { ReactNode } from "react";

export const lucra = createLucraClient({ apiKey, tenantId, env: "sandbox" });

export function App({ children }: { children: ReactNode }) {
  return <LucraProvider client={lucra}>{children}</LucraProvider>;
}
```

## Hooks

| Hook | Returns | Does |
| --- | --- | --- |
| `useLucra()` | The client | Gives components the client for calls |
| `useLucraAuth()` | `LucraAuthState` | Renders again when the auth state changes |
| `useLucraPresentState()` | `LucraPresentState` | Renders again when the screen on show changes |
| `useLucraScreen(screen, options)` | Nothing | Shows a screen while the component is mounted |
| `useMatchupWatch(matchupId)` | `{ details, error }` | Watches a matchup while the component is mounted |

Every hook must be used inside `<LucraProvider>`. Outside it, it throws.

## useLucraAuth

```tsx
import { useLucraAuth } from "lucra-web-sdk/react";

function Account() {
  const { status, user } = useLucraAuth();
  if (status === "loading") return null;
  if (status === "loggedOut") return <p>Not logged in</p>;
  return <p>{user?.username}</p>;
}
```

- See [Who is logged in](3.0_headless_client.md#who-is-logged-in) for each `status`.
- `user` can be `null` for a moment after `status` becomes `"loggedIn"`.

## useLucraScreen

Shows any `LucraScreen` while the component is mounted. For example, a route that shows the profile and leaves when the user closes it:

```tsx
import { useLucraScreen } from "lucra-web-sdk/react";

export function ProfileRoute() {
  useLucraScreen("profile", {
    onClose: () => navigate("/"),
  });
  return null;
}
```

| Option | Notes |
| --- | --- |
| `presentation` | `"fullScreen"`, `"modal"`, or `"sheet"`. Defaults to the client's. See [As a modal or a sheet](3.0_headless_client.md#as-a-modal-or-a-sheet) |
| `phoneNumber` | `login` only. Fills in the form. 10 digits |
| `onClose(result)` | Called with what the `lucra.present` call resolves. See [Showing a Lucra screen](3.0_headless_client.md#showing-a-lucra-screen) |
| `onError(error)` | Called when the call rejects, for example with `NOT_LOGGED_IN`. Without it, the rejection is unhandled |

- Unmounting closes the screen through the call's `signal`, so it never closes a screen something else opened since. `onClose` is not called then.
- A new `screen`, `presentation`, or `phoneNumber` closes the screen and shows the new one. `onClose` is not called for the old one. New `onClose` or `onError` functions on each render do not show it again.
- Not for `addFunds` or `minigame`: call those on `useLucra().present` from an event handler.
- Safe in StrictMode: one screen shows.
- One screen at a time, as with `lucra.present`. A second screen closes the first, and the first one's `onClose` gets `reason: "replaced"`. Mount one `useLucraScreen` at a time.

## useLucraPresentState

```tsx
import { useLucraPresentState } from "lucra-web-sdk/react";

function ChatButton() {
  const { screen } = useLucraPresentState();
  if (screen !== null) return null;
  return <button type="button">Chat</button>;
}
```

- `screen` is the screen on show, `"minigame"` while a game shows, or `null`. See [Reacting to the screen on show](3.0_headless_client.md#reacting-to-the-screen-on-show).

## useMatchupWatch

```tsx
import { useMatchupWatch } from "lucra-web-sdk/react";

function MatchupStatus({ matchupId }: { matchupId: string }) {
  const { details, error } = useMatchupWatch(matchupId);
  if (error) return <p>Live updates stopped</p>;
  if (!details) return <p>Loading</p>;
  return <p>{details.matchup.status}</p>;
}
```

- `details` is `null` until the first details arrive, then the latest.
- `error` is a `LucraError`, set if the watch fails. The watch has stopped then, and `details` keeps the last ones.
- Unmounting stops the watch. A new `matchupId` stops the old watch and starts over with `details: null`.
- One matchup at a time across the app, so never one per card in a list. See [Watching a matchup](3.0_headless_client.md#watching-a-matchup).

## Reading and changing data

The hooks cover the state that changes on its own. For everything else, call the client from `useLucra()`, from an event handler or your data library.

```tsx
import { useLucra } from "lucra-web-sdk/react";

function AddFundsButton() {
  const lucra = useLucra();
  return (
    <button type="button" onClick={() => void lucra.present.addFunds()}>
      Add funds
    </button>
  );
}
```

- Start [changes](3.0_headless_client.md#changing-things) from event handlers, not effects.

## Server rendering

On the server, `createLucraClient` returns a client that does nothing. On the server and while hydrating, the hooks render `"loading"` for auth, a `null` screen, and `null` details, then the browser's state. `useLucraScreen` and `useMatchupWatch` start in the browser, after hydration.
