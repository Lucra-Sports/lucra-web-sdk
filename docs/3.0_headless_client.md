# Headless client (preview)

> **This is a preview.** It ships next to `LucraClient`, which it does not change. Its API can still change while it is a preview. Tell your Lucra contact what works and what does not.

The headless client is for apps that show Lucra data in their own screens. You call a function and get data back. You draw the UI.

```typescript
import { createLucraClient } from "lucra-web-sdk/headless";

export const lucra = createLucraClient({ apiKey, tenantId, env: "sandbox" });

const tournaments = await lucra.tournaments.list();
```

Before you start, ask your Lucra contact to confirm your Lucra environment supports the headless client.

## Setup

Create the client once, when your app starts. Keep it for the life of the page.

- It starts connecting to Lucra right away. You never wait for it: every call waits on its own, except `lucra.auth.updateUser()`.
- Calling `createLucraClient` again with the same config and container returns the same client, so hot reload is safe.
- Calling it with a different config throws. Call `lucra.destroy()` first.
- Use one client per page. Do not use `LucraClient` and the headless client on the same page.
- If the client cannot connect, every call rejects and `lucra.auth` stays `"loading"`. To find out early, `await lucra.whenConnected()`. It rejects with the reason, for example `CONNECTION_FAILED` for a wrong `apiKey`.

| Option | Type | Notes |
| --- | --- | --- |
| `apiKey` | `string` | Required |
| `tenantId` | `string` | Required |
| `env` | `"sandbox" \| "production"` and others | Required |
| `locationId` | `string` | Optional |
| `autoJoin` | `boolean` | Optional. Defaults to `true`. See [autoJoin](1.2_initialize_client.md#autojoin) |
| `container` | `HTMLElement` | Optional. Shows Lucra screens inside this element instead of over the page. It must be in the page when you create the client, and stay there. See [In your own container](#in-your-own-container) |
| `presentation` | `"fullScreen" \| "modal" \| "sheet"` | Optional. Defaults to `"fullScreen"`. The default for `lucra.present` screens when there is no `container`. Each call can pass its own. Cannot be used with `container`. See [As a modal or a sheet](#as-a-modal-or-a-sheet) |

## Who is logged in

`lucra.auth` holds one state: a `status` and the `user`.

| `status` | Meaning |
| --- | --- |
| `"loading"` | Lucra has not answered yet |
| `"loggedOut"` | Nobody is logged in |
| `"loggedIn"` | A user is logged in and calls that need one will work |

```typescript
const stop = lucra.auth.subscribe((state) => {
  if (state.status === "loggedIn") {
    showAccount(state.user);
  }
});
```

- `subscribe` calls your function right away with the current state, then on every change. It returns a function that stops it.
- `lucra.auth.getState()` returns the current state. It returns the same object until something changes.
- `await lucra.auth.isLoggedIn()` waits while the status is `"loading"`, then resolves `true` or `false`. A login check that fails resolves `false`. It rejects with `TIMEOUT` when Lucra reports a logged in user but does not confirm the login within 15 seconds, with `DESTROYED` after `lucra.destroy()`, and with the connection error when Lucra cannot start.
- `state.user.balance` stays current. Lucra sends the user again whenever the balance changes.
- `await lucra.auth.logout()` signs the user out of Lucra. Call it when your user signs out of your app.

### Updating the user's details

Send Lucra what you know about the user.

```typescript
await lucra.auth.updateUser({
  firstName: "Ada",
  lastName: "Lovelace",
  email: "ada@example.com",
  address: { city: "Springfield", state: "IL", zip: "62701" },
  metadata: { externalId: "user-123" },
});
```

- Every field is optional. Only the fields you pass are sent. A field that is `null` or `undefined` is left out.
- The fields are `username`, `avatarURL`, `phoneNumber`, `email`, `firstName`, `lastName`, `address`, and `metadata`. `address` holds `address`, `addressCont`, `city`, `state` (a two letter state code), and `zip`. Anything else on the object is not sent.
- `metadata.externalId` links your user to the Lucra user for automatic settlement. Lucra stores `metadata`, so keep secrets and tokens out of it.
- Lucra uses the saved details to fill in its forms, such as identity verification. Wait for the call to resolve before you show one.
- It is sent at once, for the user who is logged in when you call it. Unlike other calls it does not wait for a login: unless the status is `"loggedIn"`, it rejects with `NOT_LOGGED_IN`.
- It is not one of the [changes](#changing-things): it never waits for one, works while a screen shows, and is safe to repeat. On failure `outcomeUnknown` is `false` even if the details were saved, so call it again.
- If Lucra restarts while it waits for an answer, it rejects with `CONNECTION_RESET` and is not sent again, because a different user may be logged in by then. Call it again with the details of whoever is logged in.
- Bad input, such as a field that is not a string or `metadata` that is not an object of strings, rejects with `INVALID_ARGUMENT` before anything is sent.

## Reading data

| Call | Returns | Needs login |
| --- | --- | --- |
| `lucra.tournaments.list()` | `LucraTournament[]` | No |
| `lucra.tournaments.get(tournamentId)` | `LucraTournamentDetail \| null` | Yes |
| `lucra.tournaments.leaderboard(tournamentId, { limit, offset })` | `LucraTournamentDetail \| null` with that page of `leaderboard.rows` | Yes |
| `lucra.matchups.get(matchupId)` | `LucraMatchup` | No |
| `lucra.matchups.getDetails(matchupId)` | `LucraMatchupDetails` | No |
| `lucra.matchups.searchByMetadata({ gameId, locationId, matchupId, matchupMetadata })` | `string[]` of matchup ids | Yes |
| `lucra.matchups.list({ limit })` | `LucraUserMatchups`: the user's totals and matchups, grouped by type and status | Yes |
| `lucra.matchups.listByTypeStatus({ type, status, limit, offset })` | `LucraUserMatchupsPage`: one page of one group | Yes |
| `lucra.achievements.list()` | `LucraAchievement[]` | Yes |
| `lucra.rewards.list({ tournamentId, viewed, claimed })` | `LucraUserTournamentReward[]` | Yes |

A call that needs login rejects with `NOT_LOGGED_IN` when nobody is logged in.

If Lucra restarts while a read is waiting, for example when `lucra.present.login()` shows, the SDK sends the read again once Lucra is back. You do not need to repeat it. The call still settles within 15 seconds of when it was first sent, or rejects with `TIMEOUT`. A read that a second restart interrupts rejects with `CONNECTION_RESET`. A read that needs login rejects with `NOT_LOGGED_IN` when the user is logged out by the time Lucra is back. A change already sent is not sent again: it rejects with `CONNECTION_RESET`, so read back before you try it again.

Tournaments, single matchups, and achievements have the same fields as the existing client's. See [Tournaments Headless](2.1_tournaments_headless.md) and [Games You Play Headless](2.2_gyp_headless.md) for what each field means.

Matchup data names other users. Do not log it or send it to analytics.

`lucra.matchups.searchByMetadata()` resolves with the ids of the logged in user's matchups that match the filters. Leave a filter out to skip it. Load a matchup with `lucra.matchups.get(id)`. `matchupMetadata` may hold personal data, so do not log it.

`lucra.matchups.list({ limit })` resolves with the user's totals and one group of matchups per type and status, each holding up to `limit` matchups. It is the user's own play and money history. Do not log it or send it to analytics. Page through one group with `lucra.matchups.listByTypeStatus()`. `type` is `"GAMES"`, `"SPORTS"`, or `"TOURNAMENTS"`, and `status` is `"IN_PROGRESS"`, `"PENDING"`, `"RESULTS"`, or `"UPCOMING"`. Ask for the next page with `offset` plus the number of matchups you received, and stop when you have `total_matchups`. `limit` must be a whole number from 1 to 50 in both calls, and `offset` in `listByTypeStatus` must be 0 or more. Lucra rejects other values with `API_ERROR`.

`lucra.rewards.list()` resolves with the rewards the user won in tournaments. Every filter is optional. Lucra marks unviewed rewards as viewed when it returns them. So a repeat with `viewed: false`, including one the SDK sends after a restart, may not return them again.

Listing achievements does not mark them viewed. To mark one, call `lucra.achievements.markViewed(userAchievementId)` with the top level `id` of an earned achievement. Its `viewedAt` is empty until it is marked. The call needs a logged in user, is safe to repeat, and is not one of the changes below, so it never waits for one. If it fails, `outcomeUnknown` is `false` even though the mark may have been recorded, so call it again.

## Changing things

| Call | Does |
| --- | --- |
| `lucra.tournaments.join(tournamentId)` | Joins a tournament |
| `lucra.tournaments.autoJoin()` | Joins the free tournaments the user qualifies for |
| `lucra.matchups.create(input)` | Creates a Games You Play matchup |
| `lucra.matchups.accept(matchupId)` | Joins a free for all matchup |
| `lucra.matchups.accept(matchupId, { groupId })` | Joins one side of a versus matchup |
| `lucra.matchups.cancel(matchupId)` | Cancels a matchup the user created |
| `lucra.rewards.claim(rewardId)` | Claims a reward the user won in a tournament |
| `lucra.achievements.claim(userAchievementId)` | Claims an achievement the user earned |

All of them need a logged in user.

**One at a time.** While one of these is running, a second one (of any kind) rejects with `IN_PROGRESS` and nothing is sent. Disable your button while a call is pending.

`rewardId` comes from `lucra.rewards.list()`. For `lucra.achievements.claim()`, pass the top level `id` (not `achievement.id`) of an achievement from `lucra.achievements.list()` that is earned (`isEarned` is true) and not yet claimed (`claimedAt` is empty).

Some failures are something the user can fix in Lucra, for example logging in or sharing their location. Run your call with `lucra.withRemediation()` and Lucra shows what the user needs, then your call runs again. It resolves with your call's result, or rejects with the error your call failed with, usually a `LucraError`, for your own UI. If the user leaves without finishing, it rejects with a `LucraError`.

```typescript
import { isLucraError } from "lucra-web-sdk/headless";

async function join() {
  try {
    await lucra.withRemediation(() => lucra.tournaments.join(tournamentId));
  } catch (error) {
    if (!isLucraError(error)) throw error;
    console.log(error.code, error.message);
  }
}
```

What Lucra shows, and how many screens, can change between releases. Do not write code that depends on it.

- Pass a function that makes one Lucra call. Everything in it may run again, possibly more than once, so a second call in it would be repeated.
- The promise stays pending while the user is in a Lucra screen. Keep your button disabled until it settles.
- Some errors still reach you, such as `INSUFFICIENT_FUNDS` today. For that one, offer a button that calls `lucra.present.addFunds()`. See [Add Funds](#add-funds).
- A call whose outcome is unknown is never run again. See [Errors](#errors).
- `lucra.present.dismiss()` ends a fix that is showing, and the call then rejects.
- Run one `lucra.withRemediation()` at a time. A second one that needs a screen takes the first one's place.
- A Lucra screen that opens under one of your own modal dialogs cannot be reached. Close the dialog first.
- It works for a read that needs a logged in user too.

**Doing it yourself.** `error.remediation` names the `lucra.present` call that fixes an error. You can show it yourself, with `lucra.present[error.remediation]()`, and decide when to try again. See [Errors](#errors) for each `remediation` and when it is `null`.

## Errors

Every rejected call rejects with a `LucraError`. Check for one with `isLucraError(error)`.

| Field | Meaning |
| --- | --- |
| `code` | What happened. See the table below |
| `message` | Text for the user. The SDK writes its own for end users. When `source` is `"lucra"`, it is Lucra's own text. `API_ERROR` text can be technical |
| `source` | `"lucra"` when Lucra reported the error for your call. `"sdk"` when the SDK raised it, for example a timeout or a connection problem |
| `hint` | Guidance for you, the developer, or `null`. Never show it to users. Always `null` when `source` is `"lucra"` |
| `remediation` | The name of the `lucra.present` call that fixes it, or `null` |
| `outcomeUnknown` | `true` when a change may have gone through anyway |

**When `outcomeUnknown` is `true`, do not try again automatically.** A second create makes a second matchup with a second buy in. Read the matchup, or ask the user, first. After a claim, read `lucra.rewards.list()` or `lucra.achievements.list()` and look at `claimedAt`.

Messages the SDK raises itself (`source: "sdk"`) are written for end users. When `source` is `"lucra"`, `message` is Lucra's own text for the user, but `API_ERROR` is a catch-all, so its text can be technical. Log `hint`:

```typescript
import { isLucraError } from "lucra-web-sdk/headless";

function errorText(error: unknown): string {
  if (!isLucraError(error)) return "Something went wrong";
  if (error.hint) console.warn(error.code, error.hint);
  return error.message;
}
```

When `createLucraClient` throws, it also logs the code and the hint to the console.

| `code` | From | Meaning | `remediation` |
| --- | --- | --- | --- |
| `NOT_LOGGED_IN` | SDK | The call needs a logged in user | `"login"` |
| `INSUFFICIENT_FUNDS` | Lucra | The balance does not cover the buy in | `"addFunds"` |
| `DEMOGRAPHIC_INFORMATION_MISSING` | Lucra | Lucra needs more profile details | `"demographics"` |
| `LOCATION_NEEDED` | Lucra | The user has not shared their location yet | `"locationGrant"` |
| `UNVERIFIED` | Lucra | The user's identity is not verified. Lucra sends this for a minigame start | `"kyc"` |
| `LOCATION_ERROR` | Lucra | The location check failed. Show `message` as it is | `null` |
| `NOT_ALLOWED` | Lucra | The user or the matchup does not allow this. Show `message` | `null` |
| `INVALID_AT_STAKE`, `INVALID_REWARD_TYPE`, `INVALID_PLAY_STYLE` | Lucra | The create or minigame start input is wrong. `message` names the field | `null` |
| `NOT_FOUND` | Lucra | No such matchup | `null` |
| `API_ERROR` | Lucra, SDK | Something else went wrong. A catch-all, so Lucra's `message` can be technical | `null` |
| `IN_PROGRESS` | Lucra, SDK | Another change is still running | `null` |
| `SCREEN_OPEN` | SDK | A Lucra screen is showing. Changes wait until it closes | `null` |
| `TIMEOUT` | SDK | Lucra did not answer within 15 seconds | `null` |
| `CONNECTION_FAILED` | SDK | Lucra refused the config. `hint` says what to check | `null` |
| `CONNECTION_TIMEOUT` | SDK | Lucra did not start within 30 seconds | `null` |
| `CONNECTION_RESET` | SDK | Lucra restarted while the call was waiting. A read is sent again once, so a read gets this only after a second restart. `auth.updateUser()` is not sent again | `null` |
| `POPUP_BLOCKED` | SDK | The browser blocked the Add Funds window | `null` |
| `CANCELLED` | SDK | A matchup watch was replaced by a watch on another matchup | `null` |
| `LOGOUT_FAILED` | SDK | Lucra did not confirm the logout | `null` |
| `INVALID_ARGUMENT`, `INVALID_CONFIG` | SDK | A bad argument or config. `hint` names it. `createLucraClient` also logs the hint to the console when it throws | `null` |
| `DESTROYED` | SDK | `lucra.destroy()` was called | `null` |
| `UNSUPPORTED_ENVIRONMENT` | SDK | There is no browser, for example during server rendering | `null` |

## Showing a Lucra screen

A few steps must use Lucra's own screens. `lucra.present` shows them. It is the only part of the client that puts Lucra on screen.

| Call | Shows | Resolves `"completed"` when |
| --- | --- | --- |
| `lucra.present.login()` | Login | The user logs in. The result carries `user` |
| `lucra.present.demographics()` | Profile details form | The form closes |
| `lucra.present.kyc()` | Identity check | The check closes |
| `lucra.present.locationGrant()` | Location request | The user shares their location |
| `lucra.present.addFunds()` | Add Funds, in its own window | The deposit goes through |
| `lucra.present.minigame(input)` | A minigame | The game closes. See [Minigames](#minigames) |
| `lucra.present.withdraw()` | Withdraw | Never. It resolves `"dismissed"` when closed |
| `lucra.present.profile()` | The user's Lucra profile | Never |
| `lucra.present.wallet()` | The user's wallet | Never |

```typescript
const result = await lucra.present.login();
if (result.status === "completed") {
  showAccount(result.user);
}
```

- Each screen except Add Funds covers the page, shows as a modal or a sheet if you set `presentation` (see [As a modal or a sheet](#as-a-modal-or-a-sheet)), or fills your `container` if you set one. Nothing shows until a screen opens, and it hides again when the screen closes.
- The user leaves a screen with Lucra's own exit control, where the screen has one (see [Limits of the preview](#limits-of-the-preview)). The screen then resolves `{ status: "dismissed", reason: "exit" }`. Calling `lucra.present.dismiss()` closes whatever screen is showing, with `reason: "dismissed"`. `dismiss()` does not close the Add Funds window.
- If Lucra cannot start again while a screen shows (`login()` always restarts it), the screen closes and rejects with `CONNECTION_FAILED` or `CONNECTION_TIMEOUT`. A game closes on any restart, with the reason `"restarted"`.
- A call still waiting when `login()` restarts Lucra follows the rule in [Reading data](#reading-data).
- One screen at a time. Showing a second one closes the first.
- All but `login()` need a logged in user.
- For `demographics()` and `kyc()`, `"completed"` means the screen finished. It does not promise the user filled it in. Try your call again to find out.
- `login()` takes an optional `{ phoneNumber }` (10 digits) to fill in the form.
- While a screen is showing, the calls under [Changing things](#changing-things) reject with `SCREEN_OPEN`.

A `"dismissed"` result says why the screen closed in `reason`:

| `reason` | The screen closed because |
| --- | --- |
| `"exit"` | The user used Lucra's exit control |
| `"dismissed"` | You called `lucra.present.dismiss()` |
| `"replaced"` | Another `lucra.present` call took its place |
| `"loggedOut"` | The user logged out inside the screen |
| `"destroyed"` | You called `lucra.destroy()` |
| `"aborted"` | You aborted the call's `signal` |
| `"restarted"` | Lucra restarted while a game was showing |

Add Funds is not one of these screens. Its `"dismissed"` result has no `reason`: it always means the user closed the window.

#### Closing only your own screen

Every screen takes an optional `signal`. Aborting it closes the screen that call opened, and nothing else. Use it when a screen belongs to a route or a component, so its cleanup cannot close a screen that something else opened since.

```typescript
const controller = new AbortController();

lucra.present.profile({ signal: controller.signal }).then((result) => {
  if (result.status === "dismissed" && result.reason === "exit") {
    // The user closed it. Leave the route here.
  }
});

// In the route's or component's cleanup:
controller.abort();
```

- Aborting does nothing once the call has finished, including when another screen replaced it. The replacement stays open.
- Aborting while the call still waits to show, for example for Lucra to connect, ends it without showing the screen.
- A signal that is aborted already resolves `{ status: "dismissed", reason: "aborted" }` at once. Nothing shows, nothing is sent, and a screen already showing stays.
- A `signal` that is not an `AbortSignal` rejects with `INVALID_ARGUMENT`. A screen already showing stays.
- `login()` takes the signal next to the phone number: `{ phoneNumber, signal }`. It takes `presentation` the same way.

The type `LucraScreen` names every screen above except `addFunds` and `minigame`, which needs an input. Use it when your own code picks which screen to show:

```typescript
import type { LucraScreen } from "lucra-web-sdk/headless";

function show(screen: LucraScreen) {
  return lucra.present[screen]();
}
```

### As a modal or a sheet

Without a `container`, screens cover the page. Set `presentation` to show them in a panel over the dimmed page instead. Set it on the client for every screen, or pass it to one `lucra.present` call for that screen only.

```typescript
import { createLucraClient } from "lucra-web-sdk/headless";

const lucra = createLucraClient({ apiKey, tenantId, env: "sandbox", presentation: "sheet" });

await lucra.present.wallet();

// This screen only. The next call without one shows as a sheet again.
await lucra.present.profile({ presentation: "modal" });
```

| `presentation` | Window 640px wide or more | Narrower window |
| --- | --- | --- |
| `"fullScreen"` | Covers the page. The default | Covers the page |
| `"modal"` | A panel in the middle of the page, up to 430px wide and 800px tall | Covers the page, like `"fullScreen"` |
| `"sheet"` | A panel at the right edge, up to 430px wide and the full height | A panel the full width, up from the bottom, with 96px of the page showing above it |

- The panel changes shape as the window crosses 640px wide, even while a screen shows. Lucra does not reload when a screen opens, closes, or changes shape.
- While a screen shows, the dimmed page cannot be clicked. A click on it or the Escape key does not close the screen. The user leaves with Lucra's own exit control, and you can call `lucra.present.dismiss()`.
- The SDK draws no close button here either. Screens that lack Lucra's exit control (see [Limits of the preview](#limits-of-the-preview)) need a `container` with your own close button.
- Every screen that shows in the page takes `presentation` next to `signal`: `login()`, `demographics()`, `kyc()`, `locationGrant()`, `withdraw()`, `profile()`, `wallet()`, and `minigame()`. It applies to that screen only, in place of the client's, including when the screen replaces another one.
- The client's `presentation` is the default for calls that pass none, and for the screens `lucra.withRemediation()` shows.
- Add Funds opens its own window and takes no `presentation`.
- A value other than `"fullScreen"`, `"modal"`, or `"sheet"` throws `INVALID_CONFIG` on the client, and rejects a call with `INVALID_ARGUMENT`. A screen already showing stays.
- `presentation` cannot be used with `container`, since a screen fills the container. Passing both to the client throws `INVALID_CONFIG`. On a client with a `container`, a call that passes `presentation` rejects with `INVALID_ARGUMENT`.
- Calling `createLucraClient` again returns the same client only with the same `presentation`. Leaving it out is the same as `"fullScreen"`.

### In your own container

Pass an element as `container` to show screens inside it instead of over the page.

```typescript
import { createLucraClient } from "lucra-web-sdk/headless";

const lucra = createLucraClient({ apiKey, tenantId, env: "sandbox", container });

closeButton.addEventListener("click", () => lucra.present.dismiss());

await lucra.present.wallet();
```

- Use an empty element. Give it a height (not only `min-height`), or make it a flex or grid item that stretches. A screen fills it.
- You can add your own close button next to it, like `closeButton` above, that calls `lucra.present.dismiss()`.
- Keep the element in the page for the life of the client. If you remove it while the client lives, calls time out and an open screen keeps waiting. If you move it, Lucra reloads and an open screen is not shown again.
- Call `lucra.destroy()` in the cleanup of whatever renders the element, for example when a component unmounts. Create the client again after. This is also how you switch to another element.
- Calling `createLucraClient` again returns the same client only when you pass the same element.

#### Showing your own wrapper

`lucra.present.getState()` returns `{ screen }`: the name of the screen on show, `"minigame"` while a game shows, or `null`. Use it to show and hide your own wrapper around the container, instead of wrapping each `lucra.present` call.

```typescript
const wrapper = container.parentElement;

const stopWatching = lucra.present.subscribe((state) => {
  if (wrapper) wrapper.hidden = state.screen === null;
});
```

- `subscribe` calls your function right away with the current state, then on every change. It is always handed the current state, so it can see the same state twice. It returns a function that stops it.
- `getState()` returns the same object until the state changes, so the pair works with React's `useSyncExternalStore`, the same way as `lucra.auth`.
- `screen` is set only while a screen is on show. A screen still waiting to show, for example for Lucra to connect, for a login, for a change to finish, or for a game to start, is not reported. Add Funds opens its own window and is never reported.
- When one screen replaces another, the first one hides before the second one shows, so `screen` goes to `null` and then to the new name. When nothing has to wait, both changes happen in the same task, before the browser paints.
- After `lucra.destroy()`, `screen` is `null`.

### Add Funds

Call `lucra.present.addFunds()` directly inside a click handler, with no `await` before it. Browsers only allow a new window during the click that asked for it. Otherwise the call rejects with `POPUP_BLOCKED`.

```typescript
addFundsButton.addEventListener("click", async () => {
  const result = await lucra.present.addFunds();
  if (result.status === "completed") {
    // result.message is text from Lucra, for example "Funds deposit successful".
  } else if (result.status === "failed") {
    statusText.textContent = result.message;
  }
});
```

Only the call that opened the window reports the deposit, so show your success message from that call alone.

| `status` | Means |
| --- | --- |
| `"completed"` | The deposit went through. `message` is Lucra's text |
| `"failed"` | The deposit failed. `message` is Lucra's text |
| `"dismissed"` | The user closed the window without finishing |
| `"alreadyOpen"` | The window was already open. This call tries to bring it to the front, which browsers may ignore |

`result.message` is text from Lucra. Show it as text, never as HTML. `"completed"` reports Lucra's success message, not a receipt. Read the new balance from `lucra.auth`.

### Minigames

`lucra.present.minigame(input)` starts a minigame session, and Lucra shows the game in its own frame. Your page never sees the game's address.

```typescript
const result = await lucra.present.minigame({ gameId: "your-game-id", mode: "1v1", amount: 5 });
if (result.status === "completed" && result.matchupId) {
  const matchup = await lucra.matchups.get(result.matchupId);
  statusText.textContent = matchup.status;
}
```

| Field | Type | Notes |
| --- | --- | --- |
| `gameId` | `string` | Required |
| `mode` | `"practice" \| "1v1" \| "free_for_all" \| "tournament"` | Required |
| `amount` | `number` | Optional. The stake. Needed for `"1v1"` and `"free_for_all"`. Ignored for practice and tournament |
| `matchupId` | `string` | The tournament id. Required for `"tournament"` and refused with any other mode |
| `signal` | `AbortSignal` | Optional. See [Closing only your own screen](#closing-only-your-own-screen) |
| `presentation` | `"fullScreen" \| "modal" \| "sheet"` | Optional. How this game shows. Not sent to Lucra. See [As a modal or a sheet](#as-a-modal-or-a-sheet) |

What each mode needs:

| `mode` | Needs |
| --- | --- |
| `"practice"` | Nothing. There is no stake |
| `"1v1"`, `"free_for_all"` | An `amount` above 0 that is one of the wager amounts the game is set up with |
| `"tournament"` | `matchupId`, the tournament id. The call joins the tournament, takes its buy in, then starts the game. Do not also call `lucra.tournaments.join()` for that play, or the user pays twice |

A refusal can carry `INSUFFICIENT_FUNDS`, `UNVERIFIED`, `DEMOGRAPHIC_INFORMATION_MISSING`, `LOCATION_NEEDED`, `INVALID_AT_STAKE`, `INVALID_PLAY_STYLE`, or `NOT_ALLOWED`. See [Errors](#errors).

| `status` | Also has | Means |
| --- | --- | --- |
| `"completed"` | `sessionId`, `matchupId` | The game closed itself |
| `"dismissed"` | `reason`, `sessionId`, `matchupId` | The game closed for `reason`, which is `"restarted"` when Lucra restarted while it showed. The ids are `null` when no session was started |

- Starting a game is a change, as in [Changing things](#changing-things), that also needs a logged in user and works inside `lucra.withRemediation()`.
- Nothing shows until the game has started. Before it sends anything, the SDK checks the shape and types: `gameId`, `mode`, an `amount` that is a number of 0 or more, a non empty `matchupId` that is present for tournament mode and absent for the others, `signal`, and `presentation`. A failed check rejects with `INVALID_ARGUMENT`. Lucra checks the rest, such as whether the amount is one of the game's wager amounts, and refuses with one of the codes above, for example `INVALID_AT_STAKE`.
- A page that sends its own `Permissions-Policy` header must allow fullscreen, autoplay, and encrypted media for its Lucra address. Otherwise the game cannot use them.
- `"completed"` means the game closed, not that the user won. For a paid game, read the result with `lucra.matchups.get(matchupId)`.
- When an error has `outcomeUnknown: true`, a game may have started and a stake may have been placed. In tournament mode it can mean the buy in was taken but the game could not start or show. Unless Lucra restarted, which removes the game itself, the SDK sends Lucra home so the game does not keep running. Read `lucra.matchups.list()` before you try again.
- Dismissing the call while the game starts waits for Lucra's answer. If the game started, the call resolves `"dismissed"` with its ids, the game does not show, and the SDK sends Lucra home.
- The call needs a Lucra environment that answers it. Until then, it rejects with `TIMEOUT` after 15 seconds. That `TIMEOUT` also has `outcomeUnknown: true` although nothing was started, because the SDK cannot tell the two apart. While it waits, `dismiss()` cannot end the call early.

## Watching a matchup

```typescript
const watch = lucra.matchups.watch(matchupId, {
  onUpdate(details) {
    console.log(details.matchup.status);
  },
  onError(error) {
    console.log(error.code);
  },
});

// Later, for example when the screen goes away:
watch.stop();
```

- `onUpdate` gets the current details first, then the full details again on every change.
- `watch()` returns right away and never throws. `stop()` is safe to call more than once.
- If the watch fails, `onError` is called once and the watch has stopped.
- Watch one matchup at a time. Two watches on the same matchup share it. A watch on a different matchup replaces it, and the old one gets `onError` with `CANCELLED`.
- No login needed.

## Events

`lucra.on(event, listener)` tells you about things the user did inside a Lucra screen. It returns a function that stops it.

| Event | Data |
| --- | --- |
| `matchupCreated`, `matchupAccepted`, `matchupStarted`, `matchupCanceled`, `activeMatchupStarted`, `tournamentJoined` | `{ matchupId }` |
| `autoJoinedTournaments` | `{ matchupIds }` |

These do not fire for your own calls. When `lucra.tournaments.join()` resolves, that is your signal.

## Cleaning up

`lucra.destroy()` closes any screen, stops the watch, and rejects calls that are still waiting with `DESTROYED`. It does **not** sign the user out. Call `lucra.auth.logout()` for that.

## Limits of the preview

- One client per page, and not together with `LucraClient`.
- Some Lucra screens do not show their own exit control yet. Show screens in a `container` with your own close button that calls `lucra.present.dismiss()`. See [In your own container](#in-your-own-container).
- Tournament data comes in the shape Lucra stores it. Cleaner shapes are planned.
- A bundler that does not read the `exports` field of `package.json` (webpack 4, for example) cannot find `lucra-web-sdk/headless`. Point an alias at `lucra-web-sdk/dist/headless/index.js`.
- If your site sends a `Content-Security-Policy` header, it must allow your Lucra address under `frame-src`: `https://<tenantId>.<env>.lucrasports.com`, or `https://<tenantId>.lucrasports.com` in production, with `tenantId` in lowercase. Without it the client never connects and calls reject with `CONNECTION_TIMEOUT`.
- `matchups.searchByMetadata`, `matchups.list`, `matchups.listByTypeStatus`, `rewards.list`, `rewards.claim`, `achievements.claim`, `achievements.markViewed`, `auth.updateUser`, and `present.minigame` are new. Where Lucra does not answer one yet, it rejects with `TIMEOUT` after 15 seconds. An unanswered claim or minigame start also holds up your other changes for that time.
